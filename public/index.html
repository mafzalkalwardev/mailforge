What is MailForge?

MailForge is a self-hosted email desk made by INDUS Web Agency. It verifies addresses one at a time or from a CSV or spreadsheet, sends campaigns through SMTP accounts you connect, and collects replies in one inbox that syncs over IMAP. The application and its MongoDB data run on a server you control.

What MailForge does

One server holds the list, the SMTP check, the campaign, and the replies. Nothing on this page is a score, a review, or a price.

Single and bulk verification

Check one address, or upload a CSV or XLSX. The email can sit in any column. truemail-go is the default engine: syntax, MX lookup, and a live SMTP RCPT dialog, with the server response saved. Disposable domains, role accounts, and known free providers are flagged from bundled lists. If auto mode is on and truemail-go is down, MailForge can fall back to Reacher. A row is valid only when SMTP confirms the mailbox.

Campaigns, senders, and warm-up

Build a campaign from a verified list, a template, and one or more SMTP accounts. Set a delay (5 to 15 seconds by default), a per-sender cap, and an optional start time. Warm-up raises each account’s daily cap over 12 days, from 20 messages toward the account limit. A campaign can also mail the sender a short warm-up note before the list goes out. Recipients are split across the accounts you select.

Templates

Templates store subject and body variants. Each send picks one of each at random. Merge fields cover name, email, state, sender, and company. New accounts include freight-dispatch copy: Freight Dispatch - INDUS Transports ships with 10 subjects and 10 bodies. If you save a Groq, OpenRouter, or OpenAI key in Settings, the template screen can draft copy. Verification does not use an LLM.

Suppression list and unsubscribe

Suppressed addresses — manual blocks, imports, bounces, complaints, and unsubscribes — are skipped. Turn on the unsubscribe link and each message includes a URL to the public unsubscribe page. Opening it adds that address with reason unsubscribe. Bounces spotted in the inbox can be suppressed too. Settings can append a postal address for CAN-SPAM.

Unified inbox

Each sender account syncs over IMAP into one inbox. Filter by account, unread, starred, important, or sent, search, and reply without leaving MailForge. Sent campaign messages show in the same place as the replies.

History, exports, settings, and proxies

History keeps single checks and bulk jobs. Export a CSV of every row or only rows marked valid, including a partial file while a job is still running. Settings chooses the engine, hosted verifier URLs, bulk concurrency, and an SMTP proxy (such as SOCKS5) when port 25 is blocked. The same screen can download a JSON backup and check SPF, DKIM, and DMARC on a sender domain.

Start from copy that is already in the app

You do not begin with a blank editor. Freight, follow-up, and introduction templates are seeded for a new account. Edit them, or add your own, then attach one when you create a campaign.

Read the answer next to the send

IMAP sync pulls each account into a single list. Switch to one sender when you only want that mailbox, or keep “All accounts” when a campaign used several.

Mailboxes you already own

Add an account with its SMTP and IMAP hosts, or import a sheet of email, app password, and name. Each account has its own daily limit, warm-up day, and DNS check. MailForge sends as those accounts. It does not provide a shared sending pool.

How to verify an email list

Four steps inside the app. The job keeps running on the server if you change pages.

  1. 1

    Create an account

    Open Log in, choose Register, and create an account on your MailForge server. After sign-in you land on the dashboard.

  2. 2

    Upload the file

    Open Bulk Verify and upload a CSV or XLSX file. The email address can sit in any column. MailForge reads the file and starts a job on the server.

  3. 3

    Let the checks run

    Each address is checked for syntax, MX records, disposable and role-account flags, and a live SMTP RCPT dialog. You can leave the page. Pause or resume the job from Bulk Verify, and download rows before the job finishes.

  4. 4

    Export the result

    From History, download every row or only rows marked valid. Valid means the mailbox was confirmed over SMTP. A rejection such as 550, or a check that could not open SMTP, is not marked valid.

Questions people ask

What is email verification?

Email verification checks whether an address is well formed and whether its mail server will accept it, before you send a campaign. MailForge does that on your server: syntax, MX lookup, disposable and role-account flags, and an SMTP conversation with the recipient server. It stores the server response instead of a score.

How does MailForge check deliverability?

MailForge checks the address and gives you sending controls. It does not promise inbox placement. truemail-go, or Reacher when that engine is selected or auto mode falls back, looks up MX records and opens an SMTP dialog: connect, EHLO, MAIL FROM, RCPT TO. The raw response is saved. SPF, DKIM, and DMARC for a mailbox you send from can be checked on the sender account. Sending speed is limited by per-account warm-up, a delay between messages, and an optional hourly cap.

What is a catch-all email domain?

A catch-all domain accepts mail for every local part, so a 250 response does not prove that one specific mailbox exists. MailForge runs the SMTP dialog with safe check enabled and keeps the server reply. If the server rejects the recipient, the address is not marked valid. If the server accepts it, MailForge records that acceptance, including on servers that accept unknown users. History styles a result labeled catch-all as a warning, the same way it styles a disposable address, rather than as a confirmed unique mailbox.

How does MailForge detect disposable email addresses?

Disposable addresses are matched against a bundled list of temporary and throwaway domains, on the server, with no call to a verification SaaS. A match is reported on the result, counted on bulk jobs, and is not treated as a valid mailbox. Role accounts such as info@ or admin@ are flagged the same way. Known free providers are labeled, and that label alone does not make the address invalid.

Can MailForge verify a bulk list from a CSV?

Yes. Bulk Verify accepts a CSV or XLSX file and finds the email address even when it is not in the first column. The job runs on the server, so you can leave the page, pause, or resume. You can download rows before the job finishes. History then exports every row or only the rows marked valid.

How do MailForge campaigns avoid spam?

MailForge does not bypass spam filters or guarantee delivery. It keeps a campaign from going out as one fast blast from a single mailbox. You can send only addresses marked valid, skip the suppression list, wait a random delay between messages (5 to 15 seconds by default), split the list across sender accounts, and cap each account with a warm-up schedule that starts at 20 messages a day and rises toward the account limit. A sender can be paused when its failure rate climbs (25% by default). Optional unsubscribe text and a postal footer can be added. You still need permission to email the list and working DNS authentication on the domain you send from.

How does MailForge handle unsubscribe requests and GDPR?

MailForge does not claim a GDPR certification. You host it, so lists, campaign history, sender credentials, and synced mail stay in MongoDB on your server and are not uploaded to a verification SaaS. If you turn the unsubscribe link on, each message can include a URL to /unsubscribe.html. Opening that link adds the address to the suppression list with reason unsubscribe, and later campaigns skip it. Bounces detected in the inbox can be suppressed too. Settings can append a physical postal address for CAN-SPAM. You remain the operator of the data.
